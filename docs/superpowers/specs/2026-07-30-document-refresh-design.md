# 文档刷新与临时文件设计

## 目标

减少重复读取造成的模型 Token 消耗，同时确保每个新任务使用当时最新的 Confluence 页面或 Redmine Issue。

## 行为

- 每个新任务首次需要文档时，重新获取并分析一次。
- 同一任务默认复用已提取的信息，不重复获取或分析。
- 仅因上下文压缩或精确核对需要时，允许重读同一份本地结果；这不属于刷新。
- 仅在用户明确要求刷新时再次获取；刷新结果替代此前依据，并告知用户已刷新。
- 不自动比较新旧全文；用户明确要求时才比较。
- 默认临时输出使用安全的随机文件名，在任务不再需要读取后删除。
- 用户显式指定的输出路径予以保留。
- Confluence 与 Redmine 遵循完全相同的生命周期约定。

## 修改范围

- 更新两个 `SKILL.md` 的获取、复用、刷新和清理说明。
- 补充自动化检查，防止两个 Skill 的约定发生偏差。
- 不修改脚本的随机文件名、显式输出路径或中间文件清理逻辑。

## 验证

- 新任务获取一次，同一任务默认复用；仅在上下文压缩或精确核对需要时重读同一本地结果。
- 明确刷新时重新获取并告知用户。
- 默认临时结果使用后删除；显式输出保留。
- 两个 Skill 文档规则一致，现有脚本测试继续通过。

## 不做

- 不建立跨任务内容缓存。
- 不保存旧文档作为后续任务依据。
- 不自动生成版本差异或持久化内容哈希。
